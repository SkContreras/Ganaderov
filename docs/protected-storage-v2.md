# Protected storage Web candidate
All normal record stores use AES-GCM envelopes, including photo bytes, operations, settings and conflict metadata. Index fields/id remain visible. Internal CryptoKeys and encrypted incremental mirror remain native syncMeta records. Cross-tab Web Locks required. Account database names include project/user/ranch. Old shared database preserved; only explicitly attributed outbox entries copied once. Old unsynced legacy bundle edits remain in original DB and need explicit recovery; no automatic import of mixed-account data. Guest migrates in place. Snapshot transactions are expensive (full store reads, photo bytes expanded to JSON); browser integration and performance tests required. Existing old tabs must close due to version bump. Key stored in same origin is not protection against XSS or malicious browser profile access. Exported backup still plaintext. No claim of complete key recovery or rotation.

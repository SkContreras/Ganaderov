# Paso 16 — concurrencia y consistencia
CI Web ejecuta sintaxis y pruebas locales en cada push/PR. El script Python usa dos conexiones PostgreSQL reales y una barrera, con fixtures UUID aleatorios. Requiere una base descartable (preferentemente Supabase local), psycopg 3 y esquema + candidatos event RPC/feed. Nunca producción; bloqueo explícito del proyecto conocido y confirmación de entorno, pero la variable no prueba que el destino sea staging. Ejecutar sin -O (asserts). Comprueba dos pesajes simultáneos, duplicado concurrente, reintento tras respuesta perdida simulada, UUID alterado, outsider, feed contiguo y revocación previa al envío. No simula fallo real de red, revocación en plena transacción, rollback concurrente del feed, jornada, edición por campo, navegador ni carga. No ejecutar contra producción. Fixtures se confirman y se limpian en finally; si falla setup o cleanup, desechar entorno. No existe staging validado ni se ejecutó SQL. La prueba de concurrencia no es una garantía de todos los casos.

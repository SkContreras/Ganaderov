# Jornadas v1 — cierre y reanudación compartidos
Candidata staging backend/journey_transitions_v1.sql, basada en finish_mobile_journey. Owner/admin autenticados, RLS invoker, bloqueo jornada y fichas ordenadas, compare-and-swap de updated_at, consentimiento explícito de cierre incompleto, IDs deterministas de eventos. Reanuda solo incomplete, conserva registros ya atendidos. Si un evento previo difiere se aborta toda transacción; no sustituir pesaje corregido ni duplicar. Antes de cerrar de nuevo, corregir diferencias mediante futura API de corrección atómica. La RPC no calcula pronósticos. La web solo invoca transición si la ficha local coincide con último fingerprint confirmado; sin fallback si RPC falla. Flag syncJourneyRpcV1:true solo staging; por defecto conserva conducta antigua. No bloquear ni eliminar flujos antiguos hasta migración completa. Asistencia aún usa CAS existente; no hay merge automático ni outbox de jornadas. Auditoría de actor histórico depende de datos preexistentes y no es garantía contra adulteración por administradores. Pruebas necesarias: cierre completo/incompleto, doble cierre, reanudar, nueva asistencia, diferencias de evento, rol trabajador, dos sesiones, revocación, pérdida de respuesta, pronósticos. No aplicado ni ejecutado.

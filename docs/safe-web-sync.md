# Protección de sincronización web

Actualizaciones de animales y jornadas condicionadas por la versión leída del servidor (modified_at / updated_at); altas con INSERT, no UPSERT. Paginación por rancho y verificación de ámbito de sesión. Conflictos simultáneos conservan ambas versiones sin diálogo de reemplazo; se muestran como pendientes. La configuración de campos conserva cambios locales cuando la revisión difiere. No existe todavía interfaz de combinación/resolución de conflictos ni outbox por operación en web. No borres IndexedDB ni reinstales PWA mientras existan conflictos pendientes. No se eliminan objetos de Storage automáticamente; se aceptan huérfanos hasta diseñar limpieza segura. Se evita sobreescribir objetos en subidas; los reintentos con objeto existente verifican bytes.

Pruebas de integración requeridas: dos administradores, web y móvil, dos registros en el mismo animal, modificación durante escritura, jornada, alta con UUID repetido, tombstone, cambio de sesión, rancho >1000 fichas y subida de foto concurrente. No se cambia SQL ni se ejecutan operaciones de producción. Las versiones antiguas de PWA pueden seguir usando escrituras inseguras hasta actualizarse; la protección definitiva requiere API transaccional y restricciones servidor.
